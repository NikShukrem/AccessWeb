1. MULTI-USER REAL-TIME SYNCHRONIZATION
================================================================================
Процесс: Синхронизация изменений между множеством пользователей в реальном времени

Описание:
- Когда пользователь вносит изменение в любую таблицу (ACID, Contracts, Finance),
  изменение немедленно отправляется на backend
- Backend сохраняет изменение в SQLite базу данных
- Backend передает информацию об изменении всем подключенным WebSocket клиентам
- Все другие пользователи видят обновление в своих браузерах < 100ms
- Процесс работает асинхронно, без блокирования интерфейса

Технология:
- WebSocket (двусторонняя коммуникация)
- Broadcast механизм на backend
- JSON сериализация событий

Время отклика: < 100 мс


2. УПРАВЛЕНИЕ ГРУЗАМИ (ACID)
================================================================================
Процесс: Создание, редактирование, удаление и отслеживание грузов

Описание:
- Добавление нового груза с 40 параметрами (КТИ номер, наименование, статус и т.д.)
- Редактирование грузов через JSON редактор
- Отслеживание статуса груза (Новая, В процессе, Доставлена)
- Автоматическое распределение по этапам доставки
- Синхронизация информации о грузе между всеми пользователями
- Удаление грузов при необходимости

Используемые поля:
- Номер КТИ (уникальный идентификатор)
- Наименование груза
- Статус (Новая, В процессе, Доставлена)
- Сумма (в разных валютах)
- Дата создания / Дата доставки
- Информация о поставщике
- ETD / ETA даты
- Таможные данные (ДТ номер, DO)
- Контейнеры
- Маршруты доставки

Сценарий Египта:
1. Пользователь 1 добавляет новый груз КТИ-00041
2. Пользователь 2 видит груз мгновенно (< 100ms)
3. Пользователь 2 редактирует статус на "В процессе"
4. Пользователь 1 видит обновление немедленно
5. Пользователь 3 видит оба обновления


3. УПРАВЛЕНИЕ ДОГОВОРАМИ
================================================================================
Процесс: Управление контрактами с отслеживанием сроков

Описание:
- Создание новых договоров с 19 параметрами
- Редактирование условий договора
- Автоматическое выделение просроченных договоров (красный фон)
- Отслеживание статуса договора (Активен, Завершен, Прерван)
- Управление суммой и лимитами
- Синхронизация информации о договорах между пользователями
- Удаление завершенных договоров

Используемые поля:
- Номер договора (уникальный)
- Предмет договора
- Контрагент
- Дата начала / Дата окончания
- Статус договора
- Сумма
- Лимит расходов
- Стадии договора
- Сроки платежей

Автоматизация:
- Красное выделение если договор просроченный (дата окончания < сегодня)
- Автоматическое уведомление пользователей о просрочке
- История изменений статуса


4. УПРАВЛЕНИЕ ФИНАНСАМИ
================================================================================
Процесс: Учет расходов с автоматическим расчетом валют

Описание:
- Создание финансовой записи с указанием суммы и валюты
- Автоматический расчет суммы в USD при импорте данных
- Отслеживание расходов по категориям
- Связь финансовых записей с договорами и грузами
- Синхронизация финансовых данных между пользователями
- Аудит всех финансовых операций

Используемые поля:
- Дата операции
- Контрагент
- Валюта (EGP, EUR, RUB, USD)
- Сумма в исходной валюте
- Сумма в USD (рассчитывается автоматически)
- Категория расхода
- Связь с договором
- Связь с грузом

Автоматическое преобразование валют:
- При импорте данных с суммой в EGP → автоматический расчет в USD
- При импорте данных с суммой в EUR → автоматический расчет в USD
- При импорте данных с суммой в RUB → автоматический расчет в USD
- Курсы валют берутся из импортируемого файла или используются настроенные


5. АУТЕНТИФИКАЦИЯ И АВТОРИЗАЦИЯ
================================================================================
Процесс: Управление доступом пользователей на основе ролей

Описание:
- Вход пользователя по логину и паролю
- Генерация JWT токена с сроком действия 12 часов
- Проверка токена при каждом запросе
- Ограничение доступа на основе роли пользователя
- Безопасное выхода из системы

Роли и права доступа:

admin (администратор)
- Полный доступ ко всем таблицам (ACID, Contracts, Finance)
- Управление пользователями
- Просмотр всех данных
- Редактирование всех данных
- Удаление всех данных

contracts (менеджер договоров)
- Доступ только к таблице Договоры
- Просмотр ACID и Finance в режиме чтения
- Редактирование своих договоров
- Добавление новых договоров
- Удаление собственных договоров

finance (финансовый аналитик)
- Доступ только к таблице Финансы
- Просмотр ACID и Contracts в режиме чтения
- Редактирование финансовых записей
- Добавление новых финансовых операций
- Удаление финансовых записей


6. REST API ОПЕРАЦИИ
================================================================================
Процесс: Базовые CRUD операции через REST API

GET /api/acid - Получить все грузы
POST /api/acid - Добавить новый груз
GET /api/acid/:id - Получить груз по ID
PUT /api/acid/:id - Редактировать груз
DELETE /api/acid/:id - Удалить груз

GET /api/contracts - Получить все договоры
POST /api/contracts - Добавить новый договор
GET /api/contracts/:id - Получить договор по ID
PUT /api/contracts/:id - Редактировать договор
DELETE /api/contracts/:id - Удалить договор

GET /api/finance - Получить все финансовые записи
POST /api/finance - Добавить новую финансовую запись
GET /api/finance/:id - Получить финансовую запись по ID
PUT /api/finance/:id - Редактировать финансовую запись
DELETE /api/finance/:id - Удалить финансовую запись


7. WEBSOCKET СОБЫТИЯ
================================================================================
Процесс: Передача событий об изменениях в реальном времени

События:
- acid_created - Новый груз добавлен
- acid_updated - Груз отредактирован
- acid_deleted - Груз удален

- contracts_created - Новый договор добавлен
- contracts_updated - Договор отредактирован
- contracts_deleted - Договор удален

- finance_created - Новая финансовая запись добавлена
- finance_updated - Финансовая запись отредактирована
- finance_deleted - Финансовая запись удалена

Все события содержат:
- Тип события (type)
- Данные об объекте (data)
- Временную метку (timestamp)

11. УВЕДОМЛЕНИЯ О ПРОСРОЧКЕ
================================================================================
Процесс: Автоматическое выделение просроченных договоров

Описание:
- Проверка даты окончания договора при загрузке таблицы
- Красное выделение строки если дата окончания < текущей даты
- Обновление статуса в реальном времени
- Синхронизация информации о просрочке между пользователями

Алгоритм:
1. Загрузить договоры из базы
2. Для каждого договора проверить: дата_окончания < сегодня
3. Если да - применить CSS класс "overdue" (красный фон)
4. При изменении статуса договора - пересчитать


12. ЗАЩИТА ДАННЫХ
================================================================================
Процесс: Безопасное хранение и передача данных

Механизмы защиты:
- Хеширование паролей (bcryptjs)
- JWT токены для аутентификации (срок 12 часов)
- CORS ограничения (только localhost или настроенный домен)
- Валидация входных данных на backend
- Защита от SQL инъекций (параметризованные запросы)
- WebSocket токен верификация

Данные передаются:
- Через HTTPS (в production)
- В защищенных WebSocket соединениях (wss://)


13. МНОГОТАБЛИЧНЫЕ ОПЕРАЦИИ
================================================================================
Процесс: Операции с несколькими таблицами одновременно

Описание:
- Связь финансовых записей с договорами
- Связь финансовых записей с грузами
- Синхронизация связанных данных
- Каскадные обновления при изменении

Примеры:
- Когда контрагент договора меняется → обновляются связанные финансовые записи
- Когда груз доставлен → автоматическое закрытие связанных финансов
- Когда договор завершен → закрытие финансовых операций


14. МАСШТАБИРУЕМОСТЬ
================================================================================
Процесс: Поддержка большого количества пользователей и данных

Особенности:
- WebSocket поддержка неограниченного количества клиентов
- SQLite WAL режим для конкурентного доступа
- Ленивая загрузка данных (по 50 записей за раз)
- Кэширование на клиенте (IndexedDB 50 MB)
- Оптимизация запросов на backend
- Готовность к миграции на PostgreSQL

Производительность:
- Поддержка 100+ одновременных пользователей
- Работа с таблицами из 1,000,000+ записей
- Отклик < 100ms для большинства операций


15. ЛОГИРОВАНИЕ И АУДИТ
================================================================================
Процесс: Отслеживание всех операций в системе

Информация логируется:
- Вход/выход пользователей
- Создание новых записей (кто, что, когда)
- Редактирование записей (старые/новые значения)
- Удаление записей
- Ошибки и исключения
- WebSocket подключения/отключения

Логи содержат:
- Временную метку (timestamp)
- Пользователя (user)
- Действие (action)
- Таблицу (table)
- ID записи (record_id)
- Старые значения (old_values)
- Новые значения (new_values)

ТЕХНИЧЕСКИЙ СТЕК
================================================================================
Backend:
- Node.js v18+

- WebSocket (ws library) - Real-time синхронизация

- JWT (jsonwebtoken) - Аутентификация
